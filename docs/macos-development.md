# macOS 开发

工程包含 Flutter macOS 桌面目标，使用项目 CI 固定的 Flutter 3.47.0。安装 Xcode 和 CocoaPods 后，在项目根目录执行：

```sh
flutter pub get
flutter run -d macos
# 或构建应用
flutter build macos
```

生成的应用位于 `build/macos/Build/Products/` 的对应构建模式目录。macOS 最低版本为 12.0。首次使用蓝牙时请在系统提示中授权；文件选择、网络客户端和蓝牙权限已在沙盒配置中声明。

macOS 桌面目标复用 Flutter 界面及 Dart 业务逻辑。BLE、文件选择等功能依赖相应 macOS 插件，仍需使用实际设备逐项验收。视频转换与播放、相机编码、热点配网、地图与导航捕获、通知监听等原有 Android 原生通道并未因此自动移植；不能认为这些功能已在 macOS 可用。应用图标当前为 Flutter 模板图标，正式分发前需替换并配置签名及公证。

## 蓝牙实机验证（2026-10-29）

在本机 macOS Debug 应用中，按厂商广播数据中的 `69:36:6B:6A:00:5B` 精确筛选 S200，连接后发现 9 个 GATT 服务并启用 JW FF03 通知；协议登录成功，读取到序列号 `69366B6A005B`、固件 `T100`、硬件 `H001`、电量及设备能力。未进行首次绑定、设置写入或完整传输验收。macOS 的设备 UUID 是系统标识，不能直接等同于广播地址；扫描列表展示厂商原始数据，六字节筛选会匹配广播中的字节序列，并不推断所有厂商数据的含义。

首次扫描会等待 CoreBluetooth 的初始状态就绪。蓝牙关闭、授权被拒绝或初始化超时仍需检查系统设置；扫描错误会写入调试日志。

### S200 历史同步验证（2026-10-29）

手表固件 T100/H001 的历史 START 含压力 `0x0e`、代谢 `0x0f`、readiness `0x10` 的数量。原解析器只接受传统类型，遇到扩展类型后主动终止会话。现已按固件 `T_HISTORY_DATA_TYPE` 映射计数，继续校验记录数量与结束标记，完成持久化后才发送确认；解析错误会保留对应原始帧供诊断。

实机按广播地址 `69:36:6B:6A:00:5B` 连接后，从健康页完成一次同步；设备页显示本轮接收睡眠 10、心率与皮温 1290、血氧 101、HRV 202、压力 471、代谢 9、readiness 9 条。日志记录确认已送达传输层；同步后连接仍保持，可重新读取电量。此结果不证明手表所有历史已取尽。此前失败批次仍保存在本机诊断记录中，健康页可能继续显示历史失败标记。

### S200 蓝牙及只读能力（2026-10-29）

使用上述 S200、T100/H001 在 macOS 应用中验证电量读取、语言原值写入并独立读回、实时心率通知的开启/接收/停止；还验证了血氧测量许可、闹钟表、支持的运动类型、时制、距离单位、亮屏时长、自动心率/血氧/血压、温度设置、健康模式、抬腕、热应激时段、勿扰和高心率提醒诊断的单项读取。屏幕亮度被设备能力位禁用。T100/H001 已开放相应只读操作及运动状态查询；运动状态查询尚未真机验证。除现有语言与实时心率功能外，配置写入和其他控制仍按原契约限制。具体读值和传感器结果会随设备状态变化。
