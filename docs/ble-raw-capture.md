# 多设备 BLE 原始数据采集

在 HoneyBox 首页选择 **数据采集**。支持 Android 和 Windows，配置保存在本机，互不共享系统之间的设备地址。

## 配置与复用

1. 点击“添加设备”，再点击“扫描设备”。可按广播名称或地址过滤；未命名设备也会显示。
   默认按信号从强到弱排序，可切换弱到强；“最低信号”可选不限或 ≥ -90 / -80 / -70 / -60 / -50 / -40 dBm，与名称/地址条件同时生效。RSSI 越接近 0，信号越强。页面显示筛选后的设备数量，信号未知的设备不参与门槛匹配。
   勾选“隐藏无名设备”可排除设备名称和广播名称均为空或只有空白的设备，首次使用不勾选；与其他筛选条件同时生效。
   信号排序、最低信号和隐藏无名设备会在修改后自动保存到本机 `capture_scan_settings.json`，下次进入添加/编辑设备页或重启应用后自动恢复，不必点击“保存配置”。它们与设备通道配置分别保存；保存或读取失败会显示提示。
2. 选择设备，等待连接及服务发现。
3. 填写配置名称，按服务勾选一个或多个 Notify / Indicate 特征。服务默认折叠，标题下显示已选特征数量；点击所需服务展开后选择特征。Read / Write 属性仅供查看，首版不做轮询或厂商命令发送。
4. 点击页面底部固定的蓝色“保存配置”按钮，或右上角白字“保存配置”。连接设备并选择至少一个通知特征后才可保存。下次打开采集应用，设备及通道会自动恢复，点击“全部开始”或单台“开始”即可。
   连接后自动收起设备结果，显示所选设备的服务和特征；再次点击扫描可重新选择设备。

每台设备独立连接和保存数据。可同时采集多台设备，也可分别停止、修改配置或删除配置。一台设备断连、订阅失败或文件写入失败，不会停止其他设备。断连后需手动重新开始；固件更换服务/特征后可重新配置。

V101 快捷选择参考 `v101_8762d_develop` 的 `debug_simple_service.h`：服务 **E0FF**，通知 **FFE1**。快捷按钮只选择实际发现的通道。硬件固件需启用该服务和数据输出；本模块不发送 FFE9 写命令。若某类传感器需要私有启动命令，先在设备端开启输出。

同一设备已有 Watch / eBadge 连接时，请先断开该连接，再进入采集。模块不会接管其他功能的连接。

## 文件与导出

应用支持目录的 `captures/capture_<唯一标识>/` 每次保存两个文件：

- `device.json`：配置名称、设备 ID、订阅通道、采集开始时间。
- `raw.jsonl`：每行一个接收到的通知包，不做解包、拼接或文本转换。

原始数据示例：

```json
{"time":"2026-10-26T00:00:00.000Z","sequence":1,"deviceId":"device-A","service":"e0ff","characteristic":"ffe1","primaryService":null,"instance":0,"hex":"00ff800a"}
```

时间是主机收到通知时的 UTC 时间，不是设备采样时间，也不代表多设备硬件时钟同步。序号在每次采集、每台设备内部递增。特征通过服务 UUID、包含服务的主服务 UUID 和特征实例区分。

界面展示包数、字节数及最多十包近期 HEX 预览；长包预览会截断，文件保留全部字节。数据持续写入文件，预览列表有固定大小。写入积压超过 4096 包会停止该设备并报告错误，不会静默声称继续记录。停止时等待队列完成并刷新、关闭文件。

停止后可点击“导出”。Android 通过系统保存对话框流式导出 JSONL，内存不随文件大小增长；Windows 选择目录，复制 JSONL 和设备元数据。“采集记录”可导出之前的记录，重启应用或删除设备配置后仍保留。Android 导出的 JSONL 每条记录自带设备和通道身份，本地 `device.json` 仍保留配置名称。

## 使用边界

采集时保持应用前台运行。返回上一页会先停止所有采集并关闭连接和文件。首版不提供 Android 后台保活、自动重连、跨平台配置导入或多设备时钟同步。系统强制结束进程或掉电时，最后未刷新的数据不保证保留。

可同时连接数量和吞吐量由操作系统、蓝牙适配器及外设决定。自动化测试覆盖并行会话、隔离、失败清理、GATT 匹配和配置恢复；实机吞吐、长时间采集和 Android 系统文件导出需要在目标设备上验收。
